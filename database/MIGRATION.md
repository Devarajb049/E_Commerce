# Database Migration Specification: MySQL/XAMPP → Supabase PostgreSQL

**Project:** ClickCart E-Commerce Cart & Order Management System  
**Migration Path:** Local MySQL / XAMPP (`ecommerce_db`) ➔ **Supabase PostgreSQL**  
**Execution:** Automated Backend Driver & Schema Migration

---

## 1. Overview of Architecture Changes

```text
BEFORE (Legacy MySQL):
Node.js/Express  ──► mysql2/promise  ──► Local MySQL 8.0 / XAMPP (Port 3306)
                                         Database: ecommerce_db

AFTER (Supabase PostgreSQL):
Node.js/Express  ──► pg (Pool)        ──► Supabase Hosted PostgreSQL 15+ (SSL)
                                         Connection: DATABASE_URL (Session / Pooler)
```

---

## 2. Converted SQL Syntax & Data Types

| Concept | Legacy MySQL (XAMPP) | Supabase PostgreSQL | Rationale |
| :--- | :--- | :--- | :--- |
| **Primary Keys** | `INT AUTO_INCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Standard ANSI SQL, prevents 32-bit overflow, Supabase standard. |
| **Table Engine** | `ENGINE=InnoDB` | *(Omitted)* | PostgreSQL uses native ACID multiversion concurrency (MVCC). |
| **Identifiers** | Backticks `` `name` `` | Standard quotes or unquoted lowercase | Standard PostgreSQL SQL syntax. |
| **String Types** | `VARCHAR`, `TEXT` | `VARCHAR(N)`, `TEXT` | Native PostgreSQL text storage. |
| **Financial Currency** | `DECIMAL(10, 2)` | `NUMERIC(10, 2)` | Exact fixed-point numeric precision for money & taxes. |
| **Timestamps** | `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` | `TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP` | Timezone-aware timestamp for international accuracy. |
| **Updated At** | `ON UPDATE CURRENT_TIMESTAMP` | PostgreSQL `BEFORE UPDATE` trigger function | Fully automated row timestamp tracking. |
| **Booleans** | `TINYINT(1)` | `BOOLEAN` | Native boolean (`TRUE` / `FALSE`). |
| **Enums & State** | `ENUM('PLACED', ...)` | `VARCHAR(50) CHECK (col IN (...))` | Native CHECK constraints allowing flexible uppercase & lowercase statuses. |
| **Upserts** | `ON DUPLICATE KEY UPDATE` | `ON CONFLICT (col) DO UPDATE SET` | PostgreSQL upsert syntax with `EXCLUDED` record references. |
| **Search Matching** | `LIKE` (case-insensitive in MySQL) | `ILIKE` | Case-insensitive regex/pattern matching in PostgreSQL. |
| **Parameter Placeholders** | `?` | `$1, $2, $3...` | Native PostgreSQL numbered positional parameters. |

## 3. Database Driver & Connection Changes

### Removed
- `mysql2`: Uninstalled from `package.json`.
- Removed `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`.

### Added
- `pg` (`pg.Pool`): High-throughput connection pooling with connection timeout and idle client eviction.
- Automatic SSL detection for Supabase hosts (`ssl: { rejectUnauthorized: false }`).
- Unified connection abstraction in `server/config/db.js` returning `[rows, meta]` format so controllers maintain clean backward compatibility.

## 4. Tables Created in Supabase

1. **`users`:** Customer and administrator accounts with bcrypt password hashes.
2. **`categories`:** Product departments with slugs and status flags.
3. **`products`:** Catalog items with price, stock, SKU, slug, and category foreign key.
4. **`addresses`:** Customer delivery addresses with `is_default` flag and user foreign key.
5. **`carts`:** Persistent shopping baskets supporting both authenticated users and guest sessions.
6. **`cart_items`:** Individual items in carts with unique `(cart_id, product_id)` constraint.
7. **`orders`:** Full transactional purchase records with subtotal, 18% GST tax, shipping fee, discount, and total.
8. **`order_items`:** Historical purchase snapshot storing immutable `product_name` and `product_price`.
9. **`order_status_history`:** Audit timeline of order fulfillment lifecycle.
10. **`order_returns`:** Customer return and refund requests.

## 6. Atomic Transaction Handling

Order placement uses dedicated PostgreSQL clients from the pool:
1. `await client.query('BEGIN')`
2. `SELECT ... FROM products WHERE id = $1 FOR UPDATE` (locks row to prevent concurrent race-condition over-selling).
3. Validate database stock $\ge$ requested quantity.
4. Re-calculate financial totals server-side directly from database prices.
5. `INSERT INTO orders ... RETURNING id, order_number, total`
6. `INSERT INTO order_items ...`
7. `UPDATE products SET stock = stock - $1 WHERE id = $2`
8. Clear active user cart in `cart_items`.
9. `await client.query('COMMIT')` (or `ROLLBACK` on error).

## 8. Deployment & Production Verification

1. When deploying to **Voroa**, **Render**, or **Railway**:
   - Add `DATABASE_URL` to the service environment variables.
   - Run `npm run build` to compile the Vite frontend.
   - Run `npm start` to start the Node.js server.
2. The Express server automatically serves the frontend SPA from `client/dist` and connects securely to Supabase PostgreSQL over SSL.
